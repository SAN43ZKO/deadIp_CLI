# deadip_cli

**Диагностика блокировки IP-адреса VPS из Российской Федерации.**

Многослойная утилита для определения факта блокировки сервера со стороны
РКН/ТСПУ с доказательной базой для обращения в техподдержку провайдера.

## Зачем это нужно

Интернет провайдеры часто блокируют IP-адреса VPS, на которых обнаружены VPN-сервисы.
Владелец теряет доступ к SSH, веб-панели и API — при этом сам сервер продолжает
работать, а из-за рубежа остаётся полностью доступен.

**Обычные `ping` и `traceroute` не дают доказательств:** ТСПУ может пропускать
ICMP, но сбрасывать TCP-сессии или рукопожатие TLS. Механизм блокировки давно
сместился со стороны РКН на сторону **провайдера пользователя**: DPI распознаёт
VPN-трафик и дропает его молча, из-за чего трасса обрывается на 2-м хопе.

`deadip` проводит многослойную проверку, собирает доказательства и формирует
готовый отчёт, который техподдержка принимает как основание для замены IP.

## Как это работает

Утилита проходит 6 независимых слоёв диагностики. Каждый слой — отдельный
источник сигнала, и решение выносится по их совокупности.

| Слой | Что проверяет | Ключевой признак |
|------|---------------|------------------|
| 1 | **ICMP ping** — 10 пакетов на целевой IP | ≥80% потерь |
| 2 | **TCP handshake** — SYN + проверка обмена данными | нет SYN-ACK на всех портах |
| 3 | **TLS handshake** — с реальным SNI | RST/EOF после ClientHello = DPI |
| 4 | **Traceroute / MTR** — TCP или ICMP режим | трасса умирает сразу за ISP |
| 5 | **Контрольная группа** — `ya.ru` теми же методами | цель недоступна, контроль доступен |
| 6 | **Globalping** — внешние пробы из РФ и ЕС | RU-пробы не видят, EU-пробы видят |

### Что учитывается в вердикте

- **AS российских хопов** определяются через [Team Cymru](https://team-cymru.com/)
  whois-резолвинг — работает без root и без флага `-z` в mtr.
- **DNS резолвится через DoH** (Cloudflare / Google), чтобы исключить подмену
  ответа российским провайдером.
- **Тристейт `data_exchange`** для TCP: `True` / `False` / `None` («не применимо
  для TLS-порта») — исключает ложное срабатывание «connect, но данные не пошли».
- **Публичный IP пользователя маскируется** в отчёте.

### Вердикты

| Вердикт | Условие |
|---------|---------|
| **Блокировка подтверждена** | ICMP + TCP провалены, контроль работает, и есть независимое подтверждение: Globalping (RU≠EU), чистый паттерн «тишина сразу за ISP» или DPI-разрыв TLS |
| **Вероятна блокировка** | 2+ признака, но нет полного набора |
| **Блокировка не обнаружена** | Всё зелёное, либо проблема симметрична для цели и контроля |
| **Неопределённость** | Данных мало (например, TCP открыт, но TLS не проходил) |

## Установка

### Linux / macOS — одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/SAN43ZKO/deadIp_CLI/master/install.sh | bash
```

Скрипт:

- определит платформу (`linux-x86_64`, `linux-arm64`, `darwin-x86_64`, `darwin-arm64`);
- скачает соответствующий бинарник из последнего GitHub Release;
- проверит SHA256;
- положит в `~/.local/bin` и пропишет в `PATH`;
- подскажет, какие системные утилиты стоит доустановить.

### Вручную

Скачайте бинарник для своей платформы со
[страницы Releases](https://github.com/SAN43ZKO/deadIp_CLI/releases) и положите
в `~/.local/bin`:

```bash
chmod +x deadip-linux-x86_64
mv deadip-linux-x86_64 ~/.local/bin/deadip
deadip --version
```


### Windows

Только через **WSL**. В Windows нет `mtr` и `traceroute` в том виде,
в котором утилита их использует — половина слоёв диагностики не отработает.

```powershell
wsl --install -d Ubuntu
# внутри WSL
curl -fsSL https://raw.githubusercontent.com/SAN43ZKO/deadIp_CLI/master/install.sh | bash
```

### Системные зависимости

`deadip` использует системные `ping`, `mtr` (или `traceroute`) через
`subprocess` — они не входят в бинарник. Установите их отдельно:

```bash
# Debian / Ubuntu
sudo apt install iputils-ping mtr-tiny traceroute

# Fedora / RHEL
sudo dnf install iputils mtr traceroute

# Arch
sudo pacman -S iputils mtr traceroute

# macOS
brew install mtr
```

Без `mtr`/`traceroute` утилита продолжит работать — слой 4 будет пропущен с
понятной пометкой в отчёте.

### Опционально: capabilities для TCP-traceroute

По умолчанию `mtr -T` требует root. Один раз выдайте capabilities, чтобы
не запускать утилиту через `sudo`:

```bash
sudo setcap cap_net_raw,cap_net_admin+eip $(readlink -f $(which mtr))
sudo setcap cap_net_raw,cap_net_admin+eip $(readlink -f $(which traceroute))
```

Проверка:

```bash
getcap $(readlink -f $(which mtr))
# /usr/bin/mtr-packet cap_net_raw,cap_net_admin=eip
```

⚠️ Обновление пакета через `apt upgrade` сбросит capabilities — их нужно
выдать заново. Для ICMP-режима (без `-T`) capabilities не нужны.

## Быстрый старт

```bash
# Базовая проверка
deadip --target 203.0.113.45

# С указанием портов и сохранением отчёта
deadip --target 203.0.113.45 --ports 22,80,443,8443 --output /tmp/report.md

# С шаблоном обращения в техподдержку
deadip --target 203.0.113.45 --support-template --output /tmp/r.md

# JSON для интеграции с мониторингом
deadip --target 203.0.113.45 --json
```

## Использование

### Параметры

| Опция | По умолчанию | Описание |
|-------|--------------|----------|
| `--target`, `-t` | — | **Обязательно.** IP или домен для проверки |
| `--ports` | `22,80,443` | Список TCP-портов через запятую |
| `--timeout` | `5.0` | Таймаут на этап, секунды |
| `--output`, `-o` | — | Путь для Markdown-отчёта |
| `--support-template` | выкл | Сгенерировать шаблон обращения в техподдержку (сохраняет в `<output>.support.md` или `deadip-<ip>.support.md`) |
| `--json` | выкл | Вывод результатов в JSON (в stdout) |
| `--no-control` | выкл | Пропустить контрольную группу (слой 5) |
| `--skip-external` | выкл | Пропустить Globalping (слой 6) |
| `--debug` | выкл | Сырые результаты в stdout |
| `--no-color` | выкл | Отключить цвета |
| `--version`, `-V` | — | Показать версию |
| `--help`, `-h` | — | Справка |

### Примеры

```bash
# Проверить домен с SNI-резолвом через DoH
deadip --target example.com

# Свой набор портов + долгий таймаут
deadip --target 203.0.113.45 --ports 22,80,443,8443,9001 --timeout 10

# Только быстрые слои (без внешних API)
deadip --target 203.0.113.45 --no-control --skip-external

# Полный отчёт + шаблон для тикета
deadip --target 203.0.113.45 \
    --output /tmp/report.md \
    --support-template

# Для cron/CI — молча, в JSON
deadip --target 203.0.113.45 --json --no-color > diag.json
```

### Что печатается в консоль

1. **Таблица слоёв** с цветными иконками: ✓ / ✗ / ~ / ?
2. **Панель вердикта** с обоснованием.
3. **Строка про дельту** с прошлым запуском, если вердикт изменился.
4. **Пути сохранённых файлов** (отчёт, шаблон).

### Что складывается в файлы

- **Markdown-отчёт** (`--output`) — таблица, вердикт, детали трассировки.
- **Шаблон обращения** (`--support-template`) — готовый текст для тикета
  на русском и английском с подставленными данными.
- **Сырой лог** — автоматически в `~/.config/deadip/logs/YYYYMMDD-HHMMSS.json`.
  Используется для сравнения с предыдущим запуском.

| 2 | TCP 80 | ❌ | timeout |

ответили только 2 хопа из 30, дальше — тишина. Это характерный признак
блокировки на стороне РКН/ТСПУ через провайдера.

Российские AS в трассе: **AS31214**.

## Шаблон обращения в техподдержку

При флаге `--support-template` утилита формирует готовый текст (RU + EN),
включающий:

- краткую сводку по всем слоям;
- **сырой вывод MTR** — главный аргумент для техподдержки;
- команду для воспроизведения;
- автоматический вердикт с обоснованием.

Шаблон сохраняется рядом с отчётом:

```bash
deadip --target 203.0.113.45 --output /tmp/r.md --support-template
# → /tmp/r.md
# → /tmp/r.support.md
```

Или без `--output` — в текущий каталог:

```bash
deadip --target 203.0.113.45 --support-template
# → ./deadip-203.0.113.45.support.md
```

## Диагностика проблем

### `MTR: not found` или `AS: —`

1. Проверьте, что `mtr` установлен:

   ```bash
   which mtr traceroute
   ```

2. Проверьте, что `mtr` понимает флаги:

   ```bash
   mtr --help 2>&1 | grep -iE "aslookup|show-ips"
   ```

   В старых сборках (`mtr-tiny` из Ubuntu 20.04) нет `--aslookup` — тогда
   AS определяются через Team Cymru автоматически.

3. Проверьте, что работает whois-порт:

   ```bash
   whois -h whois.cymru.com " -v 8.8.8.8"
   ```

   Если команда не отвечает — либо порт 43 закрыт наружу, либо Cymru недоступен.
   В этом случае AS будет определяться только из `RU_AS_FALLBACK` (жёсткий
   список российских магистральных операторов).

### `TLS: [Errno 111] Connection refused` после успешного TCP

Похоже на fail2ban со стороны сервера за предыдущие неудачные ClientHello
(до того, как был поправлен `tcp.py`). Подождите 10–30 минут либо перезайдите
с другого IP. Само по себе **не является признаком блокировки** — вердикт
будет «Неопределённость».

### `Traceback: ... raw socket: Operation not permitted`

TCP-traceroute требует `cap_net_raw`. Три варианта:

1. Запустить через `sudo -E deadip ...`.
2. Выдать capabilities (см. раздел [Установка](#установка)).
3. Ничего не делать — утилита автоматически откатится на ICMP-режим,
   AS доберутся через Cymru.

### `RU: True` в Globalping, но локально недоступно

Это **не опровергает** блокировку. DPI работает на стороне провайдеров
неравномерно: одна RU-проба может видеть сервер, ваш ISP — нет. Утилита
помечает такие случаи отдельной ремаркой в вердикте.

### Windows

Используйте WSL. Из PowerShell/cmd утилита запустится, но слои 1 и 4 будут
пустыми — в Windows нет `mtr`/`traceroute` в нужном виде.

## Разработка

### Требования

- Python 3.10+
- `ping`, `mtr` (или `traceroute`)
- Опционально `scapy` — для SYN-сканов без root

### Установка dev-окружения

```bash
git clone https://github.com/SAN43ZKO/deadIp_CLI.git
cd deadip
python3.10 -m venv .venv
source .venv/bin/activate
pip install -e .
```

Editable-установка (`-e`) позволяет править код и сразу запускать:

```bash
deadip --target 1.1.1.1 --skip-external
# или
python -m rkn_diag.cli --target 1.1.1.1 --skip-external
```

### Автоперезапуск при изменениях

```bash
pip install watchfiles
watchfiles "deadip --target 1.1.1.1 --skip-external"
```

### Логи во время разработки

Чтобы не мусорить в реальном `~/.config`, переопределите XDG-каталог:

```bash
XDG_CONFIG_HOME=/tmp/rkn-dev deadip --target 1.1.1.1
```

### Тесты и линтеры

```bash
pip install pytest ruff mypy
pytest -q
ruff check rkn_diag
mypy rkn_diag
```

### Сборка standalone-бинарника

Linux (через Docker, чтобы обеспечить совместимость по glibc):

```bash
./scripts/build-linux.sh
# → release/deadip-linux-x86_64
```

macOS:

```bash
./scripts/build-macos.sh
# → release/deadip-darwin-arm64 (или x86_64)
```

### Релиз

```bash
git tag v0.1.0
git push origin v0.1.0
```

GitHub Actions соберёт бинарники под Linux (x86_64, arm64) и macOS (Intel,
Apple Silicon), создаст Release и приложит `install.sh` + `SHA256SUMS`.

## Архитектура

```
deadip/
├── pyproject.toml
├── Dockerfile.build              # окружение для сборки Linux-бинарника
├── deadip.spec                 # конфиг PyInstaller
├── install.sh                    # one-liner installer
├── scripts/
│   ├── build-linux.sh
│   └── build-macos.sh
├── .github/workflows/
│   ├── ci.yml
│   └── release.yml
└── rkn_diag/
    ├── cli.py                    # Typer-приложение, точка входа
    ├── dns_resolver.py           # резолвинг через DoH
    ├── verdict.py                # алгоритм вердикта
    ├── report.py                 # Markdown/JSON отчёты
    ├── support.py                # шаблон в техподдержку
    ├── rawlog.py                 # сырые логи и история
    ├── plugins.py                # entry-points для плагинов
    └── checks/
        ├── icmp.py               # слой 1
        ├── tcp.py                # слой 2
        ├── tls.py                # слой 3
        ├── traceroute.py         # слой 4 + Cymru AS-lookup
        └── external.py           # слой 6 (Globalping)
```

### Расширяемость

Плагины регистрируются через entry-points в группе `rkn_diag.plugins`:

```toml
# pyproject.toml вашего плагина
[project.entry-points."rkn_diag.plugins"]
my_check = "my_package.check:run"
```

Функция плагина получает `target` и `context` и возвращает словарь:

```python
def run(target: str, context: dict) -> dict:
    return {"my_signal": True, "details": "..."}
```

## Дисклеймер

Утилита предназначена для **диагностики собственных серверов** и подготовки
обращений в техподдержку провайдеров. Она не выполняет блокировок и не
модифицирует сетевой трафик. Использует только публичные API (Globalping,
Team Cymru, Cloudflare/Google DoH) и системные утилиты (`ping`, `mtr`,
`traceroute`).

Автор не несёт ответственности за использование утилиты способами,
противоречащими законодательству вашей юрисдикции.
